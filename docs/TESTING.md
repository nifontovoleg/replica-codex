# Проверка Replica в Codex

## Повторяемые локальные проверки

Из корня репозитория, рабочим Python 3.8+:

```powershell
python -m unittest discover -s tests -v
python scripts/install_codex.py --dest "$HOME/.agents/skills"
python scripts/install_codex.py --check --dest "$HOME/.agents/skills"
python scripts/check_codex_discovery.py --out .test-artifacts/codex-discovery.json
python scripts/smoke_codex.py --skills-dir "$HOME/.agents/skills"
python scripts/check_plugin.py
```

Если выбрана другая область установки, используйте её в `--dest` и
`--skills-dir`. `--check` ничего не записывает. Не устанавливайте одинаковые
навыки одновременно в пользовательскую и проектную области.

При наличии штатного `skill-creator` можно отдельно проверить каждый каталог:

```text
python <skill-creator>/scripts/quick_validate.py replica-recon
```

Повторите для остальных 10 каталогов. Валидатор требует PyYAML, который можно
установить в отдельную среду проверки. В Windows включите UTF-8 (`python -X utf8`),
если выбранный Python использует системную кодировку при чтении файлов.

`check_codex_discovery.py` обращается к `skills/list` установленного Codex.
PASS означает: все 11 навыков обнаружены ровно по одному, включены, их названия
и стартовые запросы загружены, ошибок загрузки Replica нет. Это не проверка
визуального списка навыков открытого окна.

`smoke_codex.py` проверяет реальные установленные файлы инструментов, а не
только исходники: положительные и отрицательные исходы parity, contrast,
listing и sweep; фильтрацию отзывов без источника; одинаковые и разные PNG.
Отзывы, изображения и приложение в этой проверке искусственные. Результаты
сохраняются в `.test-artifacts/installed-smoke.json`.

## Дальнейшее тестирование в рабочем чате Codex

Выберите небольшое настоящее приложение и отдельную папку проекта. Начните с
одного сценария. Каждый запрос ниже запускается отдельно; оценивайте созданные
файлы и наблюдаемое поведение перед переходом к следующему этапу.

| Этап | Запрос | Что проверять |
| --- | --- | --- |
| Исследование | `$replica-recon Разбери <URL>, только <основной сценарий>. Разработку пока не начинай.` | `replica/recon.md`, источники, стабильные S/F-ID, CSV, неизвестные состояния помечены |
| Архитектура | `$replica-architect Спланируй эту версию по собранной карте. Используй существующий стек проекта.` | схема, API, ограничения данных, первый рабочий сценарий, отсутствие лишней смены стека |
| Дизайн | `$replica-design Подготовь дизайн-систему с нашими материалами.` | токены, компоненты и выполненная проверка контраста |
| Разработка | `$replica-build Реализуй только основной сценарий и покажи в браузере.` | взаимодействие работает; CSV отражает реально сделанное; скриншот соответствует результату |
| Backend | `$replica-backend Подключи данные основного сценария. Платежи пока в тестовом режиме.` | серверный сценарий, миграции, разграничение данных; локальные тесты отделены от live |
| QA | `$replica-test Пройди основной сценарий, ошибки и повторную отправку.` | фактический запуск тестов/браузера; воспроизведение; непройденное не помечено как PASS |
| Сравнение | `$replica-diff Сравни функции и доступные скриншоты.` | честный балл, обязательные пробелы, одинаковый размер/состояние сравниваемых экранов |
| Отзывы | `$replica-entrepreneur Найди улучшения по доступным реальным отзывам.` | источники, реальная выборка, отсутствуют выдуманные цитаты и метрики |
| Бренд | `$replica-brand Подготовь собственный бренд и проверь остатки исходного.` | доступность названий не утверждается без проверки; sweep проверяет приложение |
| Запуск | `$replica-launch Подготовь только черновики материалов запуска.` | оригинальные тексты, источники цен, listing проходит проверку |
| Развёртывание | `$replica-deploy Проведи только preflight, публикацию пока не выполняй.` | ни публикации, ни live-платежей; строгая проверка обязательных функций и список оставшихся шагов |

## Проверки ограничений

- Дайте скриншоты/описание без доступного браузера: навык должен обозначить
  неизвестное и сохранить полезные результаты по доступным данным.
- Дайте проект с путём, содержащим пробелы и кириллицу: инструменты должны
  запускаться из проекта по абсолютным путям установленного навыка.
- Оставьте одну обязательную функцию незавершённой при общем балле выше 80:
  `parity.py --require-must-have --fail-under 80` должен вернуть 1.
- Дайте отзывы без URL: они исключаются из анализа; искусственные данные
  нельзя выдавать за настоящие отзывы.
- Запросите только план: навык не должен переходить к сборке, оплатам или
  публикации из-за рекомендации следующего этапа.

Полный browser/E2E-прогон проверяет конкретное созданное приложение и провайдеры.
Прохождение тестов Python-инструментов не заменяет такой прогон.
